# Roadmap

Phases with exit gates. A gate that does not pass is documented as a negative result — that is also a result. Dates are indicative for a single person; the gate, not the calendar, decides progression.

| Phase | Indicative window | Deliverable | Exit gate |
|---|---|---|---|
| **0 · Honest repo** | now | README with real status, licence, `DATA_SOURCES.md`, working ingest (Open-Meteo + GHCN + indices), notebook 01 with real figures for the region, daily forecast-archive workflow | Someone clones the repo and reproduces a figure with one command |
| **1 · Verification** | 2–4 weeks | Daily automatic ingest (GitHub Actions), SMN connector, QC + source-discrepancy report, first real metrics in `results/`, `EVALUATION_PROTOCOL.md` in force | Leaderboard of raw ensemble vs climatology vs persistence, generated by script |
| **2 · Calibration + app v0.1** | 1–2 months | EMOS / quantile mapping, Flutter **web** app with screens 1–3 (no API server deployed — static data on Pages; no Android build this phase — owner decision 2026-11-15) | CRPSS > 0 of calibrated vs raw ensemble; public app reachable by link |
| **3 · Subseasonal + alerts** | 2–4 months | 2–6 week horizon with ML, ENSO conditioning, screens 4–5, iOS/Windows | ML model beats the Phase 2 calibration on at least one lead time, or that is documented |
| **4 · Public good + partners** | 4–6 months | Dataset and models with DOI (Zenodo), preprint or technical report, contact with university / CONICET / INTA | At least one institutional partner interested (requirement for grants) |

## App stages (after the station map)

### Place search and GPS (done, 2026-11-15)

- Goal: let a user find a place by name or by their own location and see the nearest
  PRISMA station, its distance and a warning when it is far, then open that station's
  forecast. No interpolation, no runtime geocoding, no storage of location.
- Design note: [`docs/design/LOCATION_SEARCH.md`](design/LOCATION_SEARCH.md) — acceptance
  checklist checked, with the verification status recorded there.
- Shipped: a committed GeoNames gazetteer for Argentina (`data/places/ar.json`,
  14,888 places, 1.3 MiB, built by `scripts/build_places.py`), lazily loaded on the
  first non-empty query; grouped station/place results with accent-insensitive
  exact → prefix → substring ranking; each place card shows its nearest station,
  the distance and a >100 km warning, and opens that station's forecast; "Use my
  location" through the browser geolocation API with denied / unavailable / timeout
  handling; place, user and station markers plus a link line on the map; GeoNames /
  CC BY 4.0 attribution and a privacy note in About; all ten locales.
- Verified: `flutter analyze` clean, `flutter test` 89/89, backend `ruff` + `pytest`
  clean, and the GPS path driven end-to-end in the embedded WebView2 browser with a
  simulated position (637 km to Buenos Aires, warning shown). Typed place search in
  a real browser is still unverified — Flutter web ignored synthetic text input in
  that session — so it rests on widget tests plus a direct run of the shipped
  gazetteer through the app's Dart code.

### Dark theme (done, 2026-11-18)

- Goal: Material 3 dark theme support across the app, persistent via `SharedPreferences`,
  with an AppBar toggle button, adaptive model line contrast, and responsive canvas repaints.
- Shipped: `darkTheme` with M3 seed `0xFF0B6B45`, `ThemeMode.system` / `light` / `dark`
  persistence under key `prisma_theme_mode`, single-tap AppBar toggle button before
  language selector with automatic brightness detection, and contrast-adapted `modelColor()`
  for `gfs_seamless` on dark backgrounds.
- Verified: `flutter analyze` clean, `flutter test` 99/99 passing (including `app/test/theme_test.dart`).

## Regional expansion (South America)

- **Strategy:**
  - **Immediate forecast coverage:** Open-Meteo Ensemble (GFS + ECMWF IFS) operates globally, providing immediate forecast coverage across South America using `configs/regions/south_america.yaml`.
  - **Observational bridge:** METAR airport network (ICAO aerodrome codes) acts as the initial unified, near-real-time observational backbone across South American stations.
  - **Progressive national connectors:** National meteorological services will be added progressively country-by-country as open-data endpoints, licensing terms, and payload formats are verified:
    - Chile (DMC)
    - Uruguay (INUMET)
    - Brazil (INMET)
    - Peru / Bolivia (SENAMHI)
    - Colombia (IDEAM)

- [x] Regional definition for South America (`configs/regions/south_america.yaml` with 17 representative stations across major climate zones, ICAO codes, and timezones).
- [x] METAR registered under Tier 2 (`configs/sources.yaml`).

- [ ] National meteorological service connectors (progressively added per country).

## Global planetary expansion (v0.2.0)

- **Strategy:**
  - **Immediate forecast coverage:** Open-Meteo Ensemble (GFS + ECMWF IFS) operates globally, fetching ensemble forecasts for all ~136 vetted stations worldwide with local IANA timezones.
  - **Observational bridge:** Worldwide METAR airport network (NOAA Aviation Weather Center + IEM ASOS fallback) in `backend/src/prisma/ingest/metar.py` handling global ICAO prefixes (`E*`, `L*`, `U*`, `Z*`, `R*`, `V*`, `W*`, `F*`, `D*`, `G*`, `H*`, `O*`, `Y*`, `N*`, `A*`, `P*`) with $\le 5$ station request batching, decimal RMK and integer fallback decoding, and extreme timezone handling (UTC-12 to UTC+14).
  - **Progressive national service connectors roadmap by continent:**
    - **Europe:** Deutscher Wetterdienst (DWD Germany / Open Data MOSMIX), UK Met Office (DataHub), Météo-France (Public API), AEMET (Spain OpenData), SMHI (Sweden).
    - **Asia:** Japan Meteorological Agency (JMA / JMA-Net), Korea Meteorological Administration (KMA), China Meteorological Administration (CMA), India Meteorological Department (IMD).
    - **Africa:** South African Weather Service (SAWS), WMO Regional Specialized Meteorological Centres (RSMC / WIS2.0 nodes), EUMETSAT African ground stations.
    - **Oceania & Pacific:** Australian Bureau of Meteorology (BOM API / Open Data), MetService New Zealand, Fiji Meteorological Service.
    - **Middle East:** UAE National Center of Meteorology (NCM), Israel Meteorological Service (IMS), Saudi National Center for Meteorology (NCM).
