# Use of AI in this repository

PRISMA Climate is an open-source scientific research project developed under direct human leadership with the assistance of artificial intelligence coding agents. This document describes the roles, boundaries, and verification practices governing AI assistance throughout the codebase.

---

## Division of Responsibilities

### Human Owner and Lead Researcher
The project is conceived, designed, and directed by the human owner (**Inti Sol Rodríguez Roncoroni**):

- **Scientific Direction:** Defines research hypotheses, data scope, target variables, and operational thresholds.
- **Protocol Governance:** Freezes, reviews, and formally approves evaluation protocols and dated amendments (`docs/EVALUATION_PROTOCOL.md`).
- **Methodological Decisions:** Audits calibration models (such as EMOS parameter estimation and quantile mapping formulations) and resolves statistical designs.
- **Authorization:** Authorizes repository commits, dataset releases, Zenodo deposits, and published conclusions.
- **Accountability:** Assumes sole scientific and legal responsibility for the integrity, validity, and reporting of the research.

### AI Coding Agents
Autonomous and interactive AI coding agents—including **Xiaomi MiMo (Mimo Code)** and **Google Antigravity (Gemini)**—are employed as assistive technical tools:

- **Implementation:** Draft, edit, and refactor Python and Dart/Flutter code according to specifications set by the human researcher.
- **Testing and Tooling:** Write and execute test suites, static analysis checks, and diagnostic scripts.
- **Execution:** Coordinate long-running data fetch and evaluation pipelines on authorized hardware.
- **Documentation:** Generate draft documentation, release notes, and metadata files under human review.

AI agents do **not** define research questions, modify frozen evaluation rules, or publish findings independently.

## Scientific Integrity and Verification Standards

To prevent hallucination, bias, or silent methodological divergence, the project enforces strict verification constraints:

1. **Evidence Before Assertion (OBSERVED vs. INFERRED):** Technical statements in developmental dialogues and audit records are explicitly categorized as **OBSERVED** (directly confirmed via command execution, log output, file inspection, or test results) or **INFERRED** (deductive reasoning subject to subsequent empirical confirmation).
2. **Deterministic Scripts:** Scientific metrics are never estimated or generated by generative models. Every metric reported in `results/` is produced by deterministic, standalone Python scripts (`backend/src/prisma/`) from verifiable input data.
3. **Traceability and Hashing:** Evaluation artifacts record the cryptographic SHA-256 hashes of input observation tables, station registries, and regional definitions in their run metadata (`.meta.json`).
4. **Frozen Evaluation Gates:** Operational verification results remain locked behind pre-registered milestones (such as the 15-issue-date archive maturity gate). Hindcast experiments are governed by pre-registered dated protocol amendments before execution.
5. **Automated Testing:** Code quality and numerical consistency are verified locally and in continuous integration using:
   - Python: `ruff check` (linting) and `pytest` (unit and integration tests).
   - Flutter: `flutter analyze` and `flutter test`.
